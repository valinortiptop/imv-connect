
- All address geocoding goes through `geocodeWithCache` (src/lib/geocoding.server.ts), which checks the `address_geocodes` table (key = SQL `geocode_address_key`) before calling Google via Valinor; why: each address is billed once and no-result addresses are never retried.
- Lists and maps never geocode automatically; clientes/prospects carry `geocode_status` (ok/pendiente/sin_resultado) set by triggers on address change; why: prevents repeated paid lookups on every render.
- The /admin/onboarding page is the NetSuite-exit tracker: documents live in `onboarding_items` (grouped by `area`), sessions/dev tasks/parallel-run weeks in their own `onboarding_*` tables; why: one place for IMV and Valinor to track go-live readiness.
- Valinor Studio reads onboarding progress and confirms session times via the server route `/api/public/valinor-launch-sync` (header `x-launch-key` = VALINOR_LAUNCH_SYNC_KEY, service role, rules in src/lib/launch-sync.ts); why: Supabase edge functions are blocked on this stack and the payload must never expose files, notes, amounts or valor_texto.
- The admin shell (src/routes/admin.tsx) paints sidebar + header with the shared `--sidebar` token and puts page content in a rounded card; the header title comes from `resolveAdminPageTitle` (menu label of the current route) and the header search uses `globalSearchFn` with the user's session; why: one integrated look across Valinor apps, titles never drift from the menu, and RLS decides which records each user can find.
- The admin shell content area and html/body use `overflow-x: clip`, never `hidden`, and decorative oversized backgrounds sit in an `overflow-clip` wrapper; why: `hidden` turns them into hidden scroll areas, so expanding a row jumped the page to the top.
- Shared business tables and the cliente-documentos/order-summaries/productos storage buckets are gated by `public.is_staff(auth.uid())` (user has any row in `user_roles`), never `USING (true)`; why: an account without an assigned role must not reach company data.
